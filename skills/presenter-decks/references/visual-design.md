# Visual design

Use the user's branding, reference deck, or requested style before choosing defaults. Otherwise select a consistent theme that fits the audience and subject.

## Layout

Use one clear composition per slide. Prefer flat arrangements of text and evidence over repeated dashboard cards. Use grids when the content genuinely compares repeated items, such as application states or test results.

Keep titles, labels, images, and captions aligned. Place captions near the evidence they describe. Use contrast and whitespace to establish hierarchy. Avoid crowding a slide with footers, badges, and secondary labels.

## Typography

Use the bundled Presenter fonts and style roles consistently. Keep text large enough for the audience window. Before reducing a font size, shorten the copy or select a layout with more room.

## Images and screenshots

Use images that directly support the slide. Preserve aspect ratios and do not crop away evidence. For application screenshots, record the view, inputs, and expected result in the notes or source ledger.

Do not reuse the same image on multiple slides unless repetition is intentional. Do not present generated illustrations as documentary evidence.

## Evidence

Use native Presenter tables and charts when they clarify structured data. Keep quantities, units, labels, and comparisons faithful to the source. For engineering demos, prefer real runtime screenshots over mockups when the application can produce them.
