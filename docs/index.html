Quick Start

1. Install

One command. Detects your OS and architecture automatically.

curl -fsSL https://corepunch.github.io/presenter/install.sh | sh

Or specify a version:

curl -fsSL https://corepunch.github.io/presenter/install.sh | sh -s v1.0.0

2. Generate a presentation

Ask an AI agent to create a .slides package. Or use the included demo:

presenter "demo/Nature Portfolio.slides"

3. Present

In your meeting app (Teams, Zoom, Meet), choose Share → Window and select the Presentation window. Keep Presenter View visible only to yourself.

For AI Agents

Presenter is designed for agents that generate complete presentations from source material. The agent needs nothing installed locally — it fetches everything from this website.

What the agent fetches

  • Slide format reference: skills/presentation.md — the complete XML format spec with examples
  • DTD schemas: schemas/presentation.dtd and schemas/style.dtd — formal XML validation

Agent workflow

  1. Gather all source material into an intermediate Markdown file — facts, evidence, links, quotes, metrics, screenshots
  2. Define audience, objective, central message, narrative arc, and slide outline
  3. Convert the outline into XML using the slide format reference
  4. Capture or create visuals and reference them in <image> elements with relative paths
  5. Include <notes> on every slide with a natural, ready-to-say script: context, evidence, what to emphasize, transition to the next slide
  6. Validate and review, then present live or render to images

Output format

The agent creates a .slides directory package:

My Talk.slides/
├── presentation.xml
├── images/
│   └── diagram.png
└── styles/
    └── custom.style

Minimal XML example

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE presentation SYSTEM
  "https://corepunch.github.io/presenter/schemas/presentation.dtd">
<presentation name="My Talk">
  <slide layout="title" title="My Talk">
    <notes>Welcome everyone. Today I will explain
    the three ideas that matter most.</notes>
    <subtitle>Subtitle here</subtitle>
  </slide>

  <slide layout="content" title="Key Points">
    <notes>These points form the core of the talk.</notes>
    <text icon="rocket"><b>Bold</b> point one</text>
    <text icon="none">Unmarked source or footnote</text>
    <text>Standard bullet</text>
  </slide>

  <slide layout="content" title="Q3 Results">
    <notes>Revenue accelerated through Q3.</notes>
    <chart type="bar" title="Revenue (EUR k)" icon="chart-bar">
      <point label="Jul" value="64"/>
      <point label="Aug" value="78"/>
      <point label="Sep" value="92"/>
    </chart>
  </slide>
</presentation>

Inline formatting

Use <b>, <i>, <code> for inline text formatting within <text> elements. Not markdown.

Screenshots

The agent can capture slides to PNG without a display:

presenter my-talk.slides --slide 3 --screenshot output/slide.png
presenter my-talk.slides --slide 3 \
  --screenshot output/slide.png \
  --presenter-screenshot output/notes.png

Use Cases

AI agents generating ready-to-deliver presentations — the primary use case. An agent creates XML slide files from structured data such as git history, project status, or sprint summaries, writes what the presenter should say in the notes for every slide, and optionally captures screenshots of app states as rich visual content.

1. Competitor landscape report

You need to brief your team on 5 rival products in 10 minutes. An agent fetches each competitor's homepage, extracts their pricing, positioning, and key features, scrapes their hero screenshots, and assembles a structured deck — title slide per competitor, side-by-side comparison table, and screenshot-backed talking points. What would take a human 2 hours is a single prompt.

2. Conference talk from a blog series

You wrote 4 blog posts about a technical deep-dive and got asked to give a talk on it tomorrow. An agent pulls the articles, rewrites verbose prose into bullet-pointed slides, pulls inline diagrams as standalone images, and produces a presenter-ready deck with speaker notes drawn from the original post intros. No copy-pasting, no slide design.

3. Product launch recap from social media

Your team shipped a feature and reactions are flying across Twitter, Reddit, and HN. An agent scrapes the top threads, pulls quote-worthy praise, downloads screenshots of the best reactions, and weaves them into a "launch recap" deck — timeline slide, highlight quotes, sentiment summary, and a closing slide with follow-up actions. Ready for the all-hands meeting in minutes.

Features

XML Slide Format

Recursive composition — slides nest inside slides. Directory packages keep XML, images, and styles together.

Dual-Window Output

Full audience screen + smaller presenter view with notes. Share only the audience window in meetings.

6 Layout Types

title content image columns section blank

Native Charts

Themed bar, line, pie, and donut charts directly from XML data. No external tools needed.

Named Icons

Bundled Font Awesome Free icons. Use any icon by name: icon="rocket", icon="chart-bar".

8 Built-in Themes

Switchable at runtime with Shift+Arrows. Dracula, Monokai, Solarized, Nord, and more.

Screenshot Capture

Render slides to PNG headlessly. Perfect for CI pipelines, documentation, and before/after demos.

Inline Formatting

<b>bold</b>, <i>italic</i>, <code>code</code> in text blocks.

Layouts

LayoutDescription
titleCentered title + optional subtitle (opening/closing slides)
contentTitle + vertical stack of text blocks (default)
imageTitle + full-width image + caption
columnsTitle + horizontal slots via child slides with slot attribute
sectionCentered title only (divider)
blankNo header, children fill full area

Custom styles

Define your own theme with an XML style file:

<style>
  <colors bg="#1E1E28" text="#C8C8D2" accent="#FFCC00"/>
  <charts series1="#FFCC00" series2="#56B6C2" series3="#98C379"
          grid="#646478" label="#C8C8D2"/>
  <fonts title="48" content="28"/>
  <layout margin="40" gap="24" cornerRadius="24"
          presenterCornerRadius="12"/>
</style>

Reference from your presentation:

<presentation style="./styles/dark.style">

Screenshots

Capture slides headlessly to PNG:

# Both views
presenter my-talk.slides --slide 7 \
  --screenshot output/slide.png \
  --presenter-screenshot output/notes.png

During a live presentation, press S to save the audience window or Shift+S for the presenter view.

Build from Source

Prerequisites

  • C++17 compiler
  • pkg-config
  • SDL2

tinyxml2 is vendored and built from source.

macOS (Homebrew)

brew install sdl2
make

Ubuntu / Debian

sudo apt install pkg-config libsdl2-dev
make

Run

./build/presenter "demo/Nature Portfolio.slides"

# Override theme
./build/presenter "demo/Nature Portfolio.slides" \
  --style "demo/Nature Portfolio.slides/styles/light.style"

Tests

make
./build/test_textbounds
./build/test_layout
./build/test_xml_parser
./build/test_image
./build/test_highlight

Project structure

presenter/
├── src/            # Source files
│   ├── main.cpp        # Entry point, SDL windows, event loop
│   ├── renderer.cpp    # Slide + presenter view rendering
│   ├── layout.cpp      # Slide part layout computation
│   ├── ui.cpp          # Declarative UI layout engine
│   ├── image.cpp       # Image loading and scaling
│   ├── charts.cpp      # Bar, line, pie, donut, and icon rendering
│   ├── font.cpp        # TTF font loading via stb_truetype
│   ├── highlight.cpp   # Syntax highlighting
│   ├── xml_parser.cpp  # XML → Presentation tree
│   └── style.cpp       # Theme loading + 8 built-in themes
├── include/        # Headers
├── demo/           # Example presentation and styles
├── docs/           # Website
├── test/           # Test executables
├── assets/         # Bundled fonts (Inter, JetBrains Mono, Font Awesome Free)
├── skills/         # Slide format specification
├── schemas/        # DTD validation schemas
└── Makefile
